# AGENTS.md

Desktop music player (Spotify-like clone) for **local files**: Tauri 2 + SvelteKit 3 (Svelte 5 runes, SPA via adapter-static) with a Rust backend, plus a separate Rust server for synchronized "listening groups". UI strings and user-facing errors are **French**; code and comments are English.

`CLAUDE.md` holds the detailed architecture and the "adding a feature" checklist — read it before touching group/playback code. This file is the fast ramp-up.

## Commands

```sh
cd app                          # pnpm commands run from app/
pnpm install
pnpm tauri dev                 # run the app (Vite on 127.0.0.1:1420, strictPort)
pnpm check                     # svelte-check (expected: 0 errors, 0 warnings)
pnpm lint                      # eslint + prettier --check (pnpm format to fix)
pnpm build                     # frontend production build

cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace         # also regenerates app/src/lib/bindings.ts
cargo run -p music-group-server   # env: MUSIC_SERVER_ADDR (127.0.0.1:8787), MUSIC_SERVER_DB (./server.db)
```

- Verification order: `pnpm check && pnpm lint && pnpm build` and, separately, `cargo fmt --check && cargo clippy ... && cargo test --workspace`.
- Single Rust test: `cargo test -p <crate> <test_name>`; server integration tests live in `crates/server/tests/api.rs` (`cargo test -p music-group-server --test api`).
- **`tauri::generate_context!` needs a `build/` folder**: on a fresh checkout run `mkdir -p build` before any cargo command (CI does this too).
- Second app instance for testing groups: `MUSIC_APP_PROFILE=b target/debug/music_app` — uses the first instance's Vite dev server, which must stay open; profile gets separate data/cache dirs.
- Runtime requirements: `yt-dlp` (PATH or `~/Applications/yt-dlp/yt-dlp`), `ffmpeg`, `libopus`, `node` (passed to yt-dlp as JS runtime).
- `server.db*` at the repo root are runtime artifacts of the local server — never commit them.

## Layout

One Cargo workspace (root `Cargo.toml`) + one pnpm package:

- `app/src/` — SvelteKit frontend: routes `app/src/routes/`, stores `app/src/lib/stores/*.svelte.ts`, components `app/src/lib/components/`, generated `app/src/lib/bindings.ts`.
- `app/src-tauri/` — app backend: one module per feature (`mod.rs` logic + `commands.rs` thin `#[tauri::command]` wrappers); `db/migrations/` for SQLite.
- `crates/server/` — listening-group server (axum); `crates/protocol/` — shared WebSocket types, its module doc is the protocol spec.
- Lives (`app/src-tauri/src/lives/`, `audio/live.rs`): audio plays in the rodio engine through yt-dlp + ffmpeg; the video overlay is hls.js on the `live://` scheme. See `CLAUDE.md`.
- Vite config is `app/vite.config.js` (there is **no** `svelte.config.js`). It contains a dev-only plugin that compiles a component before serving its virtual CSS; removing it breaks styling in `tauri dev`.

## Hard rules (contract)

- **Never hand-edit `app/src/lib/bindings.ts`** — it is generated by `cargo test` / debug app start (tauri-specta). It is ignored by eslint and prettier.
- **Errors**: backend returns `AppError` (`{kind, message}`, thrown in TS); frontend routes every command through `attempt()` → toast. Don't add ad-hoc error display.
- **State flows by events, never polling**: mutations return `()`, backend pushes `PlayerChanged` / `QueueChanged` / `LibraryChanged` / `PlaylistsChanged` / `GroupChanged` / etc. New state must arrive via an event listed in `specta_builder()` (`app/src-tauri/src/lib.rs`).
- **`ytdlp.rs` is the only place that spawns yt-dlp** — never through a shell, never build a URL from unvalidated input.
- **Group protocol**: server is the source of truth and broadcasts full `GroupState`; clients send intents only. Only validated YouTube ids cross the wire; never use a media URL from another member.

## Workflow gotchas

- Adding a backend feature: new module (`mod.rs` + `commands.rs`) → manage state in `setup` → register commands/events in `specta_builder()` → numbered migration in `db/migrations/` (append to `MIGRATIONS`, never edit a shipped one) → run `cargo test -p music_app` to regenerate bindings → frontend store + component.
- Frontend imports use the `#lib/...` alias **with file extension** (`#lib/stores/player.svelte.ts`).
- Prettier: printWidth 100, `prettier-plugin-svelte`; `.prettierignore` covers `*.md`, `app/src/lib/bindings.ts`, `build/`, `.claude/`.
- Do not trigger `pnpm lint` failures by editing generated/ignored files with different style — they're ignored precisely because they're generated.
